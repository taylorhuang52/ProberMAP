6 吋晶圓地圖空間演算法 (Wafer Space Mapping)

為了精確模擬真實 6 吋晶圓（6-inch Wafer）之空間幾何特性，並使預設的有效測試總顆數自動收斂於正常工業範圍（500 ~ 700 ea），系統摒棄了大矩陣設計，改採高效的二維向心收斂演算法：

1. 矩陣邊界降階

預設網頁邊界調整為 32 x 32 矩陣。此矩陣規模在結合圓形幾何切割時，能完美產出約 600 顆左右的有效晶粒。

2. 歐幾里得距離演算

定義矩陣虛擬中心點：Cx = (32 - 1) / 2 = 15.5，Cy = (32 - 1) / 2 = 15.5。針對陣列中的每一個網格 (r, c)，計算其與中心點的絕對直線距離：

Dist = √((c - Cx)² + (r - Cy)²)

3. 空間區域劃分臨界值

  • 測試區域 (Active Area)：當 Dist ≤ 半徑 - 邊緣厚度 (Radius - 1.2)，晶粒被判定為內部有效測試區，初始化時全部預設為良品代碼 (0x40)。
  • 邊緣無效區 (Edge Area)：當距離大於測試區但 Dist ≤ 半徑 時，歸類為邊緣不完整晶粒（如黃色不完全方塊）。
  • 外部跳過區 (Skip Area)：當 Dist > 半徑，直接歸類為不測試的空白背景（0x00）。

dieData.dat 狀態碼封裝與純良品初始化

dieData.dat 是機台執行晶圓測試（CP Test）或挑晶機（Pick & Place）讀取的核心地圖數據。本版本（v3.0）依產線實際需求進行了純良品重構：

1. 檔案大小硬性限制

  • UF200 (Gen1 M-LLD/LLD)：二進位緩衝區大小固定為 38,400 bytes。
  • UF2000 (Gen2 ULLD)：二進位緩衝區大小固定為 51,968 bytes。

2. 純良品初始化邏輯 (移除隨機預測)

新版程式全面移除了隨機破壞晶粒（Random Fail）的代碼。地圖初次生成時，內圈有效測試區的狀態碼全部填入 0x40，排除不確定性：

// 封裝時各狀態碼對應：
0x40 -> 主動測試良品 (Active Pass Die) -> 預設全部填入此值
0x01 -> 手動標記不良品 (Active Fail Die) -> 僅在使用者手動點擊時觸發
0x00 -> 外部跳過不測區 (Skip Die)

防止結構移位的「動態 Schema 綁定技術」

在實機架構中，參數說明檔 devList.dat 與數值檔 devParm.dat 必須在位元組層級（Byte-level）達成 100% 的絕對對齊。若發生偏離，實機會直接判定損壞（File Corrupt）。

動態綁定解決方案 (PARAM_SCHEMA)：

系統不使用硬編碼，而是將機型結構定義在中央共享對象中：

const PARAM_SCHEMA = {
    UF200_LLD: [
        { id: 1, name: "DieRowSize",  type: "uint32", offset: 12, default: 4500 },
        { id: 3, name: "FlatAngle",   type: "uint16", offset: 30, default: 180  }
    ],
    UF2000_ULLD: [
        { id: 1, name: "DieRowSize",  type: "uint32", offset: 24, default: 4500 },
        { id: 3, name: "FlatAngle",   type: "uint16", offset: 42, default: 180  }
    ]
};

協同建構機制：

  • 宣告端 (devList)：自動讀取 Schema，向機台註冊參數 ID 與對應的二進位偏移量（Offset）。
  • 賦值端 (devParm)：依據同一個 Schema 物件將 UI 輸入的值填入指定的二進位空間。源頭唯一，結構永遠對齊。

Flat Angle 限制與二進位型態防呆

使用者輸入的數值通常是不可控的，網頁系統在透過 DataView 將數值寫入二進位空間（ArrayBuffer）之前，建置了兩道核心防呆牆：

1. 參數數值邊界限幅 (Clamp 運算)

以平邊角度（Flat / Notch Angle）為例，實機暫存器僅接受 0 ~ 359 度的整數。系統在讀取 UI 值後，會強制進行限幅運算，防止極端值寫入：

let safeAngle = Math.max(0, Math.min(359, config.flatAngle));

2. 顯式型態轉換 (Big-Endian 大端序寫入)

依據 Schema 宣告的數據型態，精確調用特定長度的二進位指標寫入器，且機台預設為大端序（高點位組在前，false）：

  • uint8：調用 dv.setUint8(offset, val)，精確佔用 1 個位元組。
  • uint16：調用 dv.setUint16(offset, val, false)，精確佔用 2 個位元組。
  • uint32：調用 dv.setUint32(offset, val, false)，精確佔用 4 個位元組。

16-bit 雙位元組工業級補碼 Checksum 校驗

為防範地圖數據在網絡傳輸或儲存時發生微小損壞（Bit Flip），東京電子（TEL）機台在讀取 dieData.dat 與 devParm.dat 時，會強制執行結尾 2 個位元組的 Checksum 檢查。系統對此設計了標準二進位補碼演算：

校驗碼生成三步驟：

Step 1. 區間累加 (Byte Accumulation)：排除檔案最後 2 個位元組，使用迴圈將前面數萬個 Byte 的無符號值逐一加總。

Step 2. 16位元遮罩截斷 (Masking)：加總值可能非常龐大，將其與 0xFFFF 進行位元與（AND）運算，只保留低位元的 16-bit 空間。

Step 3. 二進位求補碼 (Two's Complement)：透過以下公式求出補碼，並將結果以大端序（Uint16）寫入檔案最後 2 個位元組：

Final_Checksum = (0x10000 - (Sum & 0xFFFF)) & 0xFFFF

當實機讀取整個檔案時，全檔加總（包含此 Checksum）的結果會剛好溢出歸零（Sum = 0），即可順利通過機台的相容性檢查。
