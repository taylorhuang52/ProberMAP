文件版本：v1.0 綜合增訂版 | 適用機型：TEL UF200 / UF2000 | 核心功能：自定義測試區與邊緣偷 Die 支援

1. 系統定位與用途

本套 Prober MAP Editor 前端網頁工具，專為半導體晶圓測試（CP, Chip Probe）產線工程師與產品工程師設計。主要用途在於因應客戶緊急改單、實驗片測試、或是機台故障復機時，能以「無須依賴複雜大型生產自動化系統（EAP）」的單機架構，快速生成完全符合東京電子（Tokyo Electron Limited）系列探針台規範的硬體地圖壓縮檔（Product.zip）。

在最新版本中，系統打破了傳統固定幾何晶圓演算法的限制，全面支援手動任意塗抹測試區與不測試區（Skip Area），並能因應 Yield 榨取實務進行邊緣不完整晶粒的「偷 Edge Die」開通針測功能，以最大化晶圓產出並提供產線最高度的靈活性。

2. 機台二進位容量規範 (Fixed-size Specifications)

早期硬體系統定址極度嚴格，TEL 機台韌體硬性規定了所有產品參數檔與地圖檔的實體空間長度。如果生成的檔案大小與規範不符，將直接引發機台軟體阻斷並扣機報錯。本工具產出的檔案大小完全符合以下硬體規範：

探針台型號 硬體規範對應代碼 規定單一檔案實體長度 (Bytes) 二進位末端填充字元 (Padding Flag)
TEL UF200 / M-LLD UF200_LLD 38,400 位元組 0x50 (ASCII 'P')
TEL UF2000 / ULLD UF2000_ULLD 51,968 位元組 0x50 (ASCII 'P')

3. 五大核心檔案與硬體暫存器架構設計

本系統導出的 Product.zip 內部包含五個關鍵二進位檔案。其底層序列化（Serialization）與記憶體位址（Offsets）完全符合硬體實體記憶體對應：

3.1 dieData.dat (晶圓地圖資料檔)

負責儲存 32x32 的晶圓二進位地圖。前 64 位元組為管理標頭（包含 Row/Col 數量及版本），第 64 位元組起為行優先（Row-Major）的 8 位元無符號整數（Uint8）矩陣。

系統全面支援動態轉化，矩陣中的每個位元組可依工程師手動點擊或演算法結果，精確序列化為以下三種工業標準狀態碼：

  • 0x40 (十進位 64)：良品晶粒 (Pass) ─ 機台會落針測試並判定為良品。
  • 0x01 (十進位 1)：不良品晶粒 (Fail) ─ 機台會落針測試並判定為不良品。
  • 0x00 (十進位 0)：不測試區 (Skip Area) ─ 機台探針座移動到此座標時，自動執行安全離合、跳過不測。

3.2 devParm.dat (產品硬體參數檔)

此檔案儲存產品的物理結構參數。系統將依據使用者在網頁填入的數值，精確尋址到特定 Offset 進行 Big-Endian 二進位複寫：

  • DieRowSize & DieColSize：晶粒幾何尺寸（預設 4500um），在 UF2000 位於 Offset 24/28，在 UF200 位於 Offset 12/16。
  • FlatAngle：晶圓平邊角度（可設 0, 90, 180, 270 度），在 UF2000 位於 Offset 42，在 UF200 位於 Offset 30。
  • PassBinCode & FailBinCode：良率判定碼（預設 64 與 1），在 UF2000 位於 Offset 44/45，在 UF200 位於 Offset 32/33。

3.3 devList.dat (參數映射索引檔)

指示機台如何解析 devParm.dat。系統在此檔案中從 Offset 12 開始，每 32 位元組劃分出一個參數指標塊，填入 Parameter ID、Offset 及型態碼（0x04=Uint32, 0x02=Uint16, 0x01=Uint8），確保硬體解碼正確。

3.4 videoData.dat 與 opParm.dat (通用對齊檔)

相機定位與作業參數檔。開頭填入 "3.00" 版本字串。Offset 11 處會自動寫入相機架構通道代碼（UF2000 寫入 0x04 4鏡頭，UF200 寫入 0x02 2鏡頭）。其餘空間依規範分別以 0x40 和 0x50 填充至指定總長度。

4. 介面與控制項說明

系統提供直覺的參數配置面板，所有欄位與硬體底層的對應邏輯如下：

網格控制項名稱 允許設定值 / 行為 對應硬體暫存器與底層邏輯
探針台型號 (Model Type) UF200_LLD / UF2000_ULLD 切換二進位檔案總容量、相機旗標及變數 Offset 定址 Schema。
平邊角度 (Flat Angle) 0°, 90°, 180°, 270° 定義實機承載台（Chuck）載入晶圓時平邊（Flat/Notch）的朝向，寫入指定 Offset。
滑鼠點擊編輯模式 (Edit Mode) 良品(Pass) / 不良品(Fail) / 不測試(Skip) 提供三種功能色彩分明的網格刷子，點擊畫布可任意開通、修改或抹除特定座標晶粒。

下載產品包 (Export Product.zip) 點擊匯出 調用 JSZip 進行全自動 Checksum 重新計算與背景二進位封裝下載。

5. 資訊統計欄位解析

面板底部的 InfoBox 區域會在每次使用者進行網格點擊、切換角度或變更機型時，即時重算最新二進位地圖內容：

  • 總計測試 (Active)：目前地圖中機台會落針測試的晶粒總ea數。
  • 良品 (Pass 0x40)：測試區域中，被標記為 Pass 的綠色晶粒數。
  • 不良 (Fail 0x01)：測試區域中，被標記為 Fail 的紅色晶粒數。
  • 總計不測 (Skip 0x00)：目前被標記為深黑色的外部背景或人工關閉（Skip）的晶粒總ea數。

6. 安全性與校驗機制 (16-bit Checksum)

為避免因磁碟損毀、網頁快取異常或傳輸失誤導致的地圖損壞，TEL 機台韌體在載入檔案（如 dieData.dat）時，會強制執行結尾 2 個位元組的 Checksum 檢查。系統對此設計了標準二進位補碼演算：

校驗碼生成三步驟：

  1. 區間累加 (Byte Accumulation)：排除檔案最後 2 個位元組，使用迴圈將前面數萬個 Byte 的無符號值逐一加總。
  2. 16位元遮罩截斷 (Masking)：將加總值與 0xFFFF 進行位元與（AND）運算，只保留低位元的 16-bit 空間。
  3. 二進位求補碼 (Two's Complement)：透過以下公式求出補碼，並將結果以大端序（Big-Endian）寫入檔案最後 2 個位元組：
Final_Checksum = (0x10000 - (Sum & 0xFFFF)) & 0xFFFF;

無論工程師手動「偷」了幾顆邊緣 Die 或是關閉了哪些區域，系統皆會在點擊匯出時重新計算。當實機載入此檔案並進行全檔加總（包含此 Checksum）時，總和將剛好發生 16 位元溢出而歸零（Sum = 0），即可順利通過機台的防損毀安全性相容檢查。

7. 產線標準操作步驟 (SOP)

生產前提醒： 請確保使用現代化瀏覽器（建議使用最新版 Google Chrome 或 Microsoft Edge）以獲得最佳的記憶體緩衝區處理效能與點擊流暢度。
  1. 開啟程式：雙擊開啟 Prober_MAP_Editor.html 網頁。
  2. 選擇目標機型：依據當前派工產線實機型號，在左側下拉選單選擇 UF200_LLD 或 UF2000_ULLD。
  3. 設定物理角度與參數：在 Flat Angle 輸入框中設定晶圓平邊角度（預設為 180）。
  4. 執行晶圓初始化：點擊 Reset Map 按鈕，畫布將依據幾何演算法自動生成標準 6 吋晶圓初始圓形網格。
  5. 自定義測試區 / 執行「邊緣偷 Die」操作：
    • 要偷邊緣 Die 時：將編輯模式切換至 🟩 標記良品 或 🟥 標記不良品，滑鼠直接移動到晶圓最外圈的「深黑色不測試背景區」，點擊該不完整晶粒。該格點將立刻被強制開通，代表解除演算法幾何限制，強行要求探針台落針測試該邊緣晶粒。
    • 要手動關閉特定 Die 時：將編輯模式切換至 ⬛ 標記為不測試 (Skip)，用滑鼠點擊任意原本是綠色或紅色的晶粒。該格點將立刻被抹黑，代表通知機台該位置為破片、空谷或不測試區，行經時安全離合、跳過不測。
  6. 確認統計數據：檢查 InfoBox 欄位，確認 Active、Pass 與 Skip 的 ea 數量與產線通知單或派工單完全相符。
  7. 匯出產品包：點擊 Export Product.zip 按鈕，即可獲得經由校驗計算過的工業標準檔案包，透過 CF 卡或網路磁碟載入實機進行成功生產。
